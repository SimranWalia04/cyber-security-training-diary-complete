## Learning Notes

Today I studied the importance of acting responsibly when learning and practising cybersecurity.

Cybersecurity tools can inspect systems and networks, so they must only be used with proper authorization. Having access to a tool does not mean I have permission to test every system.

Important concepts:

1. **Authorization:** Always get clear permission from the owner before performing security tests.
2. **Privacy:** Personal information, passwords, private files, and confidential data must be protected.
3. **Lab boundaries:** Practise in a local virtual machine, training environment, or another lab where testing is permitted.
4. **Responsible reporting:** If an issue is discovered during an authorized exercise, document it carefully and report it through the agreed process.
5. **Minimum necessary access:** Only access the information and systems required for the approved task.

Examples from my training:

- My Nmap learning should remain limited to my own lab or an explicitly authorized target.
- My AES project should use harmless sample files rather than real personal or confidential data.
- My GitHub repository should contain safe documentation and code, not passwords or encryption keys.

## Key Takeaways

- Permission must come before security testing.
- Private information must be protected.
- Practice should remain inside authorized lab boundaries.
- Security findings should be reported responsibly.
- **Important lesson:** Ethical cybersecurity means using technical knowledge to protect systems, not access or disrupt systems without permission.
